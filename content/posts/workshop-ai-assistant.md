# Building an AI Powered Workshop Assistant

In 2025, I spent an average of five hours a day doom scrolling on my phone. Thinking about all of that wasted time makes me feel awful, so this year I’ve decided I want to make a change. I needed a large-scale project that I could focus on throughout the year to give me something that is always available to work on and is easy to pick up and put down when I have a bit of free time throughout the day. I’ve been slowly working on advancing my IT skills, building out my homelab and learning new things as I go, so I wanted this project to be in that IT/Development space. Something I’ve been really interested in for a while is voice assistants and the idea of something like Jarvis to be my assistant while I work on projects---like a personalized Alexa using an LLM for complex conversations, but also with access to all of my systems like Unifi and Home Assistant. 

Another big facet of this is project management. I am horribly unorganized, and have a bad habit of saying “I don’t need to write it down. I’ll remember,” and then immediately forgetting whatever it was. I started using Notion to track my projects, so I want this tool to integrate with that as well. Ideally it would be able to create a new project page, edit documents with progress updates or other information, and organize pages based off a set structure so I can just talk to it about what I’m working on and it can document for me. Anyone who has ever played D&D with me knows that I am terrible at taking notes and I always regret not being better about it.

I’ve been using Claude AI as an assistant in a lot of my recent projects. I’ve been strictly using it as a helper, making sure that I always make my own best effort before asking Claude for help, and when I do ask for help, specifically asking for guidance and not the final answer. It has been invaluable in my Python learning process, because I can ask questions about code I’m writing and it will give me the guidance I need to figure out the answers on my own. Sort of like a mentor to point me in the right direction so I don’t get lost down a rabbit hole of research for a minor issue. For this project, I’m going to be integrating with the Claude API to handle the more complex requests and hopefully allow for conversational requests, rather than the one line questions and answers you would normally use with a voice assistant. 

Since API use costs money based off of how many tokens I use, I want to put an emphasis on budget. I don't want to accidentally use $100 of tokens in a month and get shocked by a huge bill. I’m planning on tracking usage and reporting it in the UI so I can always see my current spend for the month. Later on, I’ll look at expanding that to show things like projected spend reporting, rate limiting, and cutoff thresholds. There are also some pieces of the voice pipeline that could potentially cost money, like some of the TTS APIs, so I would want to track that usage as well.

## Why I’m Doing This

At the end of 2025, I saw year in review posts from all of the maker accounts that I follow online. I do my best not to compare my situation to others, but it’s tough to see others getting so much interesting work done and knowing that I haven’t done much. To be fair, I do have a one-year-old who takes up most of my time, and I’d usually rather hang out with him than do anything else, but I still had plenty of free time last year that could have been spent being more productive. My average screen time on my phone last year was around five hours per day, sometimes as high as seven. That’s almost all time that I could have spent working on things to improve myself. I’m not trying to beat up on myself and say that I did nothing, but I could have done better.

Going into 2026, I’m making a commitment to myself. I need to be healthier, physically and mentally. I need to eat better and get to the gym, but I also need to spend my time doing things that aren’t just mindless doom scrolling. I’m not cutting out the doom scrolling completely, sometimes it’s a good way to unwind, but I need to think about how I can spend those 5 hours a day improving myself. Rather than opening Instagram and scrolling for hours, I can work on a coding project, or read a book, or build something in my workshop. I just need to make choices with the mindset of becoming the best version of myself that I can be.

I decided the best way for me to do that is to have a project goal for the year. It had to be something that I could stretch out over the entire year and break up into achievable goals, that way I can come back in 12 months and see how I did. I’ve dealt with ADHD my whole life and one of my biggest problems is abandoning projects when they get too hard. By laying this out in advance and publicizing it as I go on my blog and Instagram, I’m hoping I can keep my interest up and actually finish it. If I have set goals to achieve, I’ll hopefully get that dopamine boost that the ADHD brain craves every time I finish one. 

## The Plan

I’ve broken the current project plan up into five phases, roughly spreading them out over the year to set myself some soft deadlines. This lets me focus on the separate pieces of the app without worrying about aspects that aren’t needed yet. It will start out as a very basic voice assistant and slowly evolve into the full vision. The hope is that this plan keeps me from getting overwhelmed and lets me get the quick wins that keep the dopamine flowing and keep me motivated. Right now, the planned phases are:

### Phase 0: Foundation Building (I’m here now.)

I’m still very much a beginner in coding, and still learning the basics of Python. My current project, Vanvalor, is a discord scheduling bot to help with planning our weekly D&D games. This is something that I actually need, since the other scheduling bots I’ve found don’t exactly fit my needs and scheduling our game with parts of our group on the other side of the world has been difficult. This project also serves to teach me asynchronous coding, which I will definitely need for the workshop assistant. Before I can even get started with the workshop assistant program, I want Vanvalor to be functional, even if it is basic.

There are some other skills I need to learn before getting started like working with the Notion and Claude APIs, database management, and error handling, but other than Notion, those skills are going to be covered with the scheduler bot project. Once I get all of that to a point where I am relatively comfortable, I think I’ll be ready to move on to the assistant project.

### Phase 1: Building a Basic Voice Assistant

The lowest level of this project is going to be an app that runs on my workshop computer, a Raspberry Pi 5 8GB, that is listening for a wake word and then can respond to simple requests. This would be things like basic math calculations and things that could be accomplished with a quick google search. I’m going to need to sort out hardware at some point, a microphone to listen and speakers to respond, but in the beginning I’ll just use what I have on hand. Currently I think I’ll be using an Audio-Technica condenser mic and a Focusrite Scarlett 2i2 interface to connect it to the Pi. Then I can just use my regular speakers for output, a set of Mackie studio monitors that I’ve had forever. This is just the hardware I already have that will do the job well enough for the development and testing. The nice thing is I already own all this audio gear from previous projects, so my hardware cost for this build is literally $0. Later on if I find the performance lacking, I can adjust as needed.

The main work in this phase will be developing the voice pipeline. The app will listen for a wake word with something like Porcupine and then pass the feed off to a speech to text processor like Vosk or Whisper. Then I can process that request depending on what it is. Questions could be searched online, calculations can be processed locally, etc. Finally, I need to set up text to speech to speak the response back to me. Google and OpenAI both have TTS APIs that are very natural sounding, but they both cost money per request, which goes against my budget. There are free alternatives, like pyttsx3 and Coqui, but their voices aren't as natural sounding, so I’ll have to test out the different options and see where I end up.

### Phase 2: Claude Integration

Once the voice pipeline is working, I’ll work on adapting that command routing to pass certain queries to the Claude API. This way I can talk to Claude about ongoing projects and problems and get responses read aloud. The basic “Alexa” functionality would still exist, so things like a quick web search or local calculations don't have to touch the Claude API at all. Currently I just use Claude through the web client, this would just make the process hands free. Claude already handles conversations really well, so I just need to learn how the API works and fit that into my system. Anthropic makes a python library for the Claude API, so hopefully that is relatively straightforward. 

The biggest hurdles in this phase are going to be token usage tracking (for the budget) and context management. If I’m having longer conversations with the assistant for something I’m working on, token usage grows exponentially since each query and response gets added to the conversations context. This means that Claude is reading the entire conversation each time it answers a question. I will need to build in logic to automatically clear context when moving to a new topic, and to condense conversations when they get too long to shrink the context and preserve token usage.

This will also be the phase where I build the token tracking system, to make sure I don’t suddenly spend hundreds of dollars when I accidentally create an endless loop in the AI. Since there is no way to test this build without using the paid API, this is critical. The basic plan is to have the system log every API call in the background and add the count of tokens used to a database. Then using the current cost of tokens, I can get a very accurate estimate of how much I am spending. I’ll also add logic to set dollar amount thresholds. My ideal budget would be around $10-$20 per month. So when I hit $15, it would give a warning, and then when I hit $20, it would block any further API calls without authorization. I’ve seen too many horror stories of people accidentally spending hundreds on cloud usage or APIs when they didn't realize it was happening, so I definitely want to avoid that at all costs.

### Phase 3: Creating a GUI

Since this will be running on my workshop computer, which has an always on monitor, I want a simple interface to show me that the program is running and listening. The idea is a small icon in the taskbar that shows the assistant is ready, then when it hears the wake word, it would change to an icon indicating it is listening. Once I’m done speaking, the icon would show that it is thinking, and then finally it would change to indicate that it is responding, before going back to the ready state. This just gives a quick glanceable UI so I know what it is doing in any given moment. 

Clicking on that icon would open a bigger menu, giving details like current API spend, projected spend, and other metrics. I could also have a configuration menu in there to change various settings if needed, like changing audio devices, changing the wake word, setting budget limits, or other things like that. 

Making a GUI will also allow the assistant to give visual responses when needed. So if I ask for something like a wiring diagram or cad file for a project I’m working on, or a YouTube video about something I’m researching, it should be able to bring that up on the screen. This way, it becomes more than a question and answer machine, it can actually show me visuals related to the things I’m working on.

So far in my development journey, I haven't done any UI development other than basic prints and queries in the terminal. I’m really looking forward to this phase and learning how to make a functional and nice looking UI to serve this project.

### Phase 4: Project Management

Currently, I’m using Notion to track my projects. I have a project doc template that I use to create new project pages in Notion so I can keep things organized. My current workflow involves explaining the project to Claude and having it fill out the template, I import it to Notion, and then I go through and flesh it out there. In a hope to automate that a bit, I want to give this assistant access to the Notion AI so it can do more of that process for me. 

My goal is to be able to tell it to create a new project page in Notion, and then it would do that and start filling in the template as I explain the project. Then I can edit the page as needed as I go through the project. Since the assistant has access to my Notion through the API, it would be able to see all of the edits I make and make its own edits whenever I need it to. This removes the janky system I use now of having to send Claude the current file each time I work on it so it stays up to date. The more of this process I can automate, the more organized I’ll be and the better I’ll feel about the work I’m doing. Personally, there is nothing that takes the wind out of my sails in a hobby more than getting frustrated over things that should be simple. Having well-written and well-organized documentation will hopefully give me a better foundation to avoid those frustrating moments and allow me to devote my time to actually building things.

For any projects involving coding, I save my code to various GitHub repos. Claude already has access to my GitHub repos and it can update itself on the latest code I’ve written, so this is something I want to carry over to this assistant project. It would be great if a git push would automatically generate an update to the Notion project file so I can have changes tracked there as well. It might be overkill, since GitHub tracks all my changes, but it would let me see the entire project in Notion and only have to check GitHub if I need the actual code.

### Phase 5: Workshop Integration

Up until this point, the assistant will be able to manage my projects and hobbies as long as they're on the internet. This phase is a bit nebulous, but the plan is to slowly build integrations to my workshop. The current plans are to give it access to Home Assistant, Unifi, and Octoprint. I want it to be able to access Home Assistant so it can turn the lights on and off, show me security camera feeds, and access other smart home devices. Unifi will be useful when I’m working with my homelab, so I can ask it questions like “What is the IP of that new server” or “What is my current WAN throughput”. Octoprint will be useful for any projects involving my 3D printer. I should be able to ask it to upload files to Octoprint and start printing them, get status updates on running prints, view the printers camera feed, and adjust various settings if needed. This phase will definitely be ongoing and change quite a bit as I think of new integrations I want to add. Ideally, there would be a menu inside the GUI for these integrations---Something that allows me to give the assistant the relevant API keys or credentials or change settings specific to certain integrations.
